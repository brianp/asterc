**Status:** Decided

Defines error and nullability handling for Aster. Single-inheritance error hierarchies via `extends`, `throw`/`throws` keywords, propagation via `!`, recovery via `!.or()` / `!.or_else()` / `!.catch`, and separate `T?` nullable types with a four-operation API.

## Key Decisions

- **Error hierarchy**: `Exception` (root) → `Error` (app base). Error types use `extends` for single inheritance.
- **`throw` keyword** for raising errors. No string shortcuts — always structured, matchable types.
- **`throws ErrorType`** on function signatures (no parens).
- **`!` propagates** errors to the caller. Stacktrace is built incrementally through each `!`.
- **Recovery**: `!.or(default)` for eager fallback, `!.or_else(-> expr)` for lazy recovery, `!.catch` for match-style branching on error type.
- **`T?` nullable types** with `.or()`, `.or_else()`, `.or_throw(Error)`, and `match`. No optional chaining, no `== nil`, no `.map()`.
- **Clean separation**: `!` is exclusively for errors, `?` is exclusively for nullability.
- **No `try`/`catch`** — dropped as redundant. One mechanism only.
- **`main()` cannot throw**. Unrecoverable faults surface as `Exception`.
