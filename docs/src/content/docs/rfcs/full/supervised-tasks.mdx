## 1. Motivation

`detached async` tasks that throw log the error and die. For long-running
background workers (queue processors, watchers, listeners), this isn't
enough. You want automatic restart with backoff.

Most languages require external tooling for this (systemd, Kubernetes,
Erlang/OTP supervisors). Aster could make it a language-level feature.

## 2. Open Questions

- Keyword (`supervised async`) or utility function?
- Backoff strategy: fixed, exponential, jitter? Configurable?
- Max retries -- then what? Log and give up? Call a handler? Crash?
- What state resets on restart? Fresh function call from scratch?
- Supervisor trees -- can you supervise groups of tasks?
- Relationship to `async scope` -- does a supervised task live inside a scope?
- Health checks / heartbeats?
- Graceful shutdown semantics

## 3. Inspiration

- Erlang/OTP supervisor trees (one_for_one, one_for_all, rest_for_one)
- Kubernetes restart policies (Always, OnFailure, Never)
- systemd service restart with backoff

## 4. Rough Sketch

```
# Supervised detached task -- restarts on failure
supervised async process_queue()
  retries: 5
  backoff: exponential

# After 5 failures -- logs final error, gives up
# Each restart is a fresh function call
```
