This page is the successor to the old planning documents and status tracker. Every
verdict below was verified against the code and test suite in August 2026 — plan
frontmatter and old trackers had drifted badly (several plans marked "in progress"
were finished; several "implemented" claims were stale), so treat this page, not the
plan files, as current. Unfinished work is inventoried thematically on the
[Roadmap](/reference/roadmap/) page.

## Language

**Shipped and test-covered:** the full protocol arc — named-only arguments, enums with
payload variants and destructuring patterns, `Self` typing, parametric traits,
auto-derived `Eq`/`Ord`/`Printable`, `From`/`Into` with expected-type resolution and
fallible `Int.from` / `to_int()`, `Iterable`/`Iterator` with a 14-method vocabulary,
`Drop`/`Close`, `DynamicReceiver`/`method_missing`, `FieldAccessible`, ranges
(`1..10`, `1..=10`) with `std/random`, `const`, enforced `pub` visibility, `Set[T]`,
map literals, string interpolation, and the caller-side async model
(`async`/`blocking`/`detached async`) with must-consume task tracking (E027) and
data-sharing warnings (W002).

**Open language work** (detail on the [Roadmap](/reference/roadmap/)):

| Item | Status |
|---|---|
| Hash trait / non-string Map keys | Not started — runtime Map is a linear-scan, string-keyed store; Set/Map went Eq-gated instead |
| Iterable long tail (`reject`, `take`, `skip`, `zip`, `flat_map`, `group_by`, `sort_by`, `to_map`) | Not started |
| String / Map as Iterable | Not started |
| Match guards, block-bodied arms, if-expressions | Not started (match itself is an expression) |
| Compound assignment (`+=`), `??`, bitwise operators, string repetition | Not started |
| `super()` dispatch, general method overloading, trait-conflict resolution | Not started (only `from()` is overloadable today) |
| BigInt auto-promotion | Not started — interim i64 overflow handling; RFC exists |
| Indirect async calls (`async (expr)()`) | Unsupported — the one remaining codegen gap-analysis item |

## Execution path

**Complete.** All milestones of the original codegen plan landed: FIR with a
Serialize-able module format, Cranelift JIT and AOT sharing one translation layer and
one Rust runtime staticlib (the planned separate C runtime was superseded, not
skipped), monomorphized generics, typed error tags with multi-arm `catch` dispatch,
class/enum lowering, iterables, and top-level statements. The parity contract is
enforced by tests: a coverage meta-test over every FIR expression variant plus an
audited list of the remaining `UnsupportedFeature` sites, and the E028 gate turns
unlowerable features into a clean "not executable yet" diagnostic instead of a crash.

## Concurrency

**Runtime: mostly complete.** Assembly context switching (x86-64/aarch64), M:N
work-stealing scheduler, safepoint-based cancellation and preemption, epoll/kqueue
I/O poller, blocking pool, shadow-stack GC integration, and AOT parity — all real,
all tested end-to-end.

**Primitives: partial, with three known correctness gaps** (see
[#49](https://github.com/brianp/asterc/issues/49) for the related GC question):

1. **Cancellation skips user cleanup** — a green thread cancelled at a safepoint
   flips to `Cancelled` without running `Close`/`Drop` on live locals.
2. **`mutex.lock(block:)` can leak the lock** — unlock is emitted straight-line
   after the inlined body rather than as a cleanup local, so a `throw` inside the
   block (or cancellation) skips the release. Escape analysis and the planned
   `timeout:`/`LockTimeoutError` are also absent.
3. **`MultiSend`/`MultiReceive` are surface-only** — `clone_sender`/`clone_receiver`
   return the same handle; no reference counting, no close-on-last-drop EOF
   semantics, no multi-producer tests.

Also open: data-sharing warnings only track the `async f(x)` boundary (channel sends
cross silently), and `main()` runs on the OS main thread behind a condvar rather
than as a green thread — a deliberate deviation from the original design that has
not been formally decided.

## Watch items

Small standing rules the audit surfaced that nothing currently enforces:

- **Token budget** — the lexer sits at exactly 70 `TokenKind` variants against a
  self-imposed ceiling of 76 (Go has 77). No test asserts the count; adding one
  would mechanize the rule.
- **Diagnostic code stability** — codes have been silently reassigned in the past
  (see [#50](https://github.com/brianp/asterc/issues/50)); append-only is the
  intended policy.
